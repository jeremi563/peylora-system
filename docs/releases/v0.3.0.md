# Peylora v0.3.0: Financial Reconciliation & Money Recovery

**Status:** Implementation milestone complete; release tag and GitHub Release publication require maintainer approval.

## Summary

Peylora v0.3.0 completes settlement reconciliation as a separate evidence and review process. Provider confirmation, financial allocation and bank settlement remain distinct concepts.

## Included implementation

- Merchant-scoped CSV/Excel settlement evidence imports.
- Operator-managed settlement source profiles.
- SHA-256 duplicate-import recognition and immutable original evidence.
- Canonical settlement batches, lines, adjustments and bank deposits.
- Exact merchant-scoped matching against Provider Transactions.
- Append-only amount, date, currency, duplicate and ambiguity exceptions.
- Manual merchant bank account and deposit evidence.
- Settlement batch-to-bank-deposit reconciliation.
- ADMIN record-only exception/match resolution.
- Immutable reconciliation runs and merchant-readable snapshots.

## Database changes

- Added settlement source profile and evidence import tables.
- Added canonical settlement batch, line, adjustment and bank-deposit tables.
- Added settlement match and reconciliation-exception tables.
- Added merchant bank account and batch/deposit match tables.
- Added reconciliation run and immutable snapshot tables.
- All settlement records remain merchant-scoped and preserve evidence history.

## API changes

- CSV/XLSX settlement evidence profile and import endpoints.
- Merchant settlement import and snapshot read endpoints.
- Merchant bank-account and bank-deposit endpoints.
- Settlement batch/deposit reconciliation endpoints.
- ADMIN settlement exception/match resolution endpoints.
- Existing payment, invoice, allocation and webhook APIs remain unchanged.

## Financial integrity

- STK/provider success is not inferred to establish settlement.
- Matching requires authoritative source fields and Merchant scope.
- Settlement evidence and operator resolution do not mutate Provider Transactions or accounting ledgers.
- Missing Provider Transaction evidence remains an exception.
- Duplicate imports and references are detected rather than silently merged.
- Reconciliation runs retain immutable historical snapshots.

## Known limitations and deferred scope

- Actual refunds and provider reversals are not implemented.
- Settlement-account money movement and settlement corrections are deferred.
- Operator resolution is record-only and cannot alter accounting or Provider Transactions.
- PDF/OCR automation is not an unconditional evidence authority.
- No official Safaricom settlement-payout API is assumed; CSV/Excel and manual evidence remain the MVP sources.
