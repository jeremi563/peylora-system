You are the senior frontend engineer and UI/UX designer responsible for building the complete frontend of this project.

Your task is to inspect the existing repository, understand the backend/API architecture and existing functionality, and then build a polished, production-quality frontend for the payment management platform.

IMPORTANT: Do not treat this as a generic dashboard template. The final product should look like a real software company built it, with a carefully designed visual identity, consistent spacing, typography, navigation, responsive behavior, and professional UX.

## 1. PRODUCT CONTEXT

This is a web-based payment management SaaS platform built around M-Pesa payments.

The platform allows businesses/merchants to:

- Manage their payment activity
- Initiate M-Pesa STK Push payments
- Track payment status
- View transactions
- Create payment requests
- Create and manage payment links
- Create invoices
- View payment analytics
- Manage customers
- Manage notifications
- Manage their account and subscription
- View system activity and audit information where permitted

The backend already contains payment-processing functionality and M-Pesa integration.

Do NOT replace, duplicate, or bypass existing backend functionality.

The frontend must consume the existing REST API through a clean API/service layer.

Before writing significant frontend code:

1. Inspect the repository.
2. Understand the existing backend routes and API contracts.
3. Inspect existing frontend files if they exist.
4. Identify the existing authentication flow.
5. Identify payment, transaction, customer, invoice, payment-link, subscription, notification, and dashboard endpoints.
6. Reuse existing functionality rather than creating fake implementations.
7. Do not invent API endpoints when an existing endpoint can be used.
8. If an API endpoint required by the UI does not exist, clearly identify it instead of silently creating fake data.
